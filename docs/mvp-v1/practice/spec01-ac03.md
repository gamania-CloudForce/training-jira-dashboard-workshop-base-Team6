# Acceptance Criteria for US-003: RD 成員查看個人與團隊進度

---

### **AC-01: 成功查看專案整體進度**

**場景**：RD 團隊成員查看儀表板以了解專案全貌

```gherkin
Given 我是一位已登入的 RD 團隊成員
And 我正在查看視覺化儀表板
When 我沒有選擇任何個人篩選器
Then 儀表板應顯示整個專案的關鍵指標，包含「總 Issue 數量」、「總 Story Points」、「已完成 Issue 數量」與「已完成 Story Points」
And 我應該能看到專案整體的「狀態分布圖」，了解各階段的任務數量
```

### **AC-02: 成功查看個人任務完成狀況**

**場景**：RD 團隊成員專注於自己的工作項目

```gherkin
Given 我是一位已登入的 RD 團隊成員
And 儀表板上有多個屬於不同成員的任務
When 我點擊「只看我的任務」的篩選器或按鈕
Then 儀表板上的關鍵指標應更新，只計算分配給我的任務
And 「狀態分布圖」應更新，只顯示我個人任務的狀態分布
And 我能清楚看到自己已完成與未完成的任務統計，感受到進度的緊迫感
```

### **AC-03: 儀表板資料即時性**

**場景**：後端資料更新後，儀表板能反映最新狀態

```gherkin
Given 我是一位已登入的 RD 團隊成員
And 我正在查看儀表板
And 後端的 Jira 資料剛被同步更新（例如：一個任務剛被標示為「完成」）
When 我刷新儀表板或系統自動更新
Then 儀表板上的「已完成 Issue 數量」和「已完成 Story Points」應立即增加
And 我能相信儀表板反映的是最新的專案狀態
```

### **AC-04: 處理無個人任務的邊界情況**

**場景**：RD 團隊成員在當前 Sprint 中沒有被分配任何任務

```gherkin
Given 我是一位已登入的 RD 團隊成員
And 當前的專案或 Sprint 中沒有任何任務分配給我
When 我點擊「只看我的任務」的篩選器
Then 儀表板應顯示「您目前沒有已分配的任務」的提示訊息
And 各項統計數據應顯示為 0
```

### **AC-05: 處理資料載入失敗的異常情況**

**場景**：因網路或後端問題導致儀表板資料無法載入

```gherkin
Given 我是一位已登入的 RD 團隊成員
And 系統無法從後端成功獲取進度資料
When 我開啟或刷新儀表板頁面
Then 系統應顯示一個清晰的錯誤提示，例如「資料載入失敗，請稍後再試」
And 提供一個「重試」按鈕，讓我能手動觸發資料重新載入
```
